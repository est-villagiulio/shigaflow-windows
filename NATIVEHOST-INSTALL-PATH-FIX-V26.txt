Shigaflow v26 — browser capture works from any install folder

Problem: the native host looked for app-path.txt only in %LOCALAPPDATA%\Shigaflow\NativeHost, but
"Connect Shigaflow to Chrome" writes it next to the installed host. When Shigaflow was installed
somewhere else (for example D:\Program\Shigaflow) the host could not find the app, every browser
handoff failed, and Chrome's own Save As dialog was all that appeared.

Fix (NativeHost/Program.cs): the host now finds Shigaflow.exe by trying, in order:
  1. app-path.txt next to the host exe
  2. app-path.txt in %LOCALAPPDATA%\Shigaflow\NativeHost (script installs)
  3. the installer layout: <install>\NativeHost\ + ..\App\Shigaflow.exe
No re-registration is needed; only the native host executable changes.

Without rebuilding, a workaround is to copy app-path.txt into the default folder:
  New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\Shigaflow\NativeHost" | Out-Null
  Copy-Item "<install folder>\NativeHost\app-path.txt" "$env:LOCALAPPDATA\Shigaflow\NativeHost\app-path.txt" -Force

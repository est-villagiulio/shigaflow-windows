SHIGAFLOW – BROWSER CAPTURE FIX

This package includes the updated Shigaflow source and browser integration.

Fix in this build:
- Native Messaging no longer rejects an extensionless download URL before Shigaflow can inspect its response headers. This supports common download endpoints that provide the filename through Content-Disposition.
- Shigaflow itself still applies the AllowedExtensions setting after it resolves the real filename.
- Browser extension manifest version is 1.0.1.

To install/update browser integration:
1. Build/install Shigaflow using the included installer scripts.
2. Run Install-BrowserIntegration.ps1 from the extracted project folder.
3. In Chrome/Edge, open the extensions page, enable Developer mode, and choose Load unpacked. Select the installed BrowserExtension folder shown by the script.
4. Copy the extension ID into the script when prompted.
5. Completely restart the browser.

If the extension is already loaded, open chrome://extensions or edge://extensions and press Reload after replacing its files.

Note: The browser integration supports HTTP/HTTPS links. Sites that require browser-only cookies, blob URLs, or special JavaScript download flows may not be transferable as a plain URL.


Version 1.0.4: Google Drive capture now recognizes Drive menu items rendered as role=menuitem, searches nested actionable ancestors, and reports when the file ID cannot be identified.


Version 1.0.5 adds Google Drive authenticated download handoff using short-lived, Google-domain-scoped cookies passed only over local native messaging. Cookies are not persisted.

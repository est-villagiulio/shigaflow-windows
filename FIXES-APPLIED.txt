Shigaflow fixes applied
=======================

1. Fixed CS1012 in Shigaflow/AppSettings.cs by using valid C# character literals
   for carriage return, newline, and tab separators: '\r', '\n', and '\t'.

2. Added persistent download history at:
   %LOCALAPPDATA%\Shigaflow\downloads.json

   The app now saves download records and progress automatically, reloads them on
   startup, keeps completed-file entries, and marks downloads that were interrupted
   while the app was closed as Cancelled so the existing Resume action can restart
   them. Existing downloaded files are not deleted by this history feature.

Build note: this environment does not have the .NET SDK installed, so a Windows/WPF
build could not be run here. Open Shigaflow.sln in Visual Studio 2022 and build
Release to verify on Windows.


Version 1.0.5 — Google Drive authenticated downloads
- Captures the selected file ID from Google Drive My Drive rows and Download menu actions.
- Reads only Google-domain cookies through the extension cookies permission.
- Passes session cookies only over Chrome Native Messaging to the local app.
- Uses a Google-domain-scoped CookieContainer for probe and download requests; cookies are not persisted in history/settings.
- Adds BrowserCookie transfer through the native host and app named pipe.
- Keeps early interception; Chrome downloads are not started for a recognized Drive Download command.

Version 1.0.6 — Downloads header and torrent metadata resilience
- Downloads page now uses a simple "File Download" title; removed the large main-content logo and tagline.
- Centered the existing sidebar logo horizontally while preserving the sidebar brand text and navigation.
- The initial MonoTorrent DHT/cache tuning was superseded by the libtorrent-rasterbar migration documented in LIBTORRENT-MIGRATION-NOTES.txt.
- Added clearer metadata-state text that distinguishes peer discovery/metadata retrieval from payload downloading.
- The app cannot force a magnet to obtain metadata if its info-hash has no reachable metadata-capable peers, or if the network/firewall blocks all discovery paths. Public tracker injection is intentionally not forced because it can leak private-torrent info-hashes.
- Build verification is still required on Windows with the .NET 8 SDK; this environment does not include the Windows/WPF build toolchain.


2026-11-11 — Torrent metadata and Torrents page consistency
- Added fallback public tracker announce URLs to magnet links that do not already contain tracker URLs.
- Kept existing magnet tracker URLs unchanged.
- Set a dedicated DHT UDP port (55124), separate from the peer listener (55123).
- Matched the Torrents heading and + Add button placement/style to Downloads.
- Added matching Select, Clear List, sort, and sort-direction controls to Torrents.
- Added torrent bulk-selection checkboxes. Bulk selection and Clear List only target completed/seeding, stopped, and errored entries; active and paused transfers remain.
- Clearing torrent entries stops them and keeps downloaded data on disk.
